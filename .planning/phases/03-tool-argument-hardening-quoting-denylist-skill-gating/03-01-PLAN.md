## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM → Skill argv | LLM-emitted `arguments` string for `execute_skill` crosses into the OS process boundary. Before Plan 01: the string was interpolated into a `cmd.exe /c py "script" {args}` shell command, giving cmd.exe full metacharacter parsing authority over LLM-supplied bytes. After Plan 01: the string is a single ArgumentList element handed directly to `py.exe` / `powershell.exe`; cmd.exe is no longer in the chain. |
| LLM → run_command | Carve-out per REQUIREMENTS.md SEC-04: `run_command` keeps `cmd.exe /c {command}` because the human types and approves the command verbatim in the Phase 1 modal. ExecuteAsync(string) is preserved by this plan to honor that contract; CommandConfirmationWindow is the access-control gate (out of scope this plan; lives in Phase 1 / Plan 02 / Plan 03). |

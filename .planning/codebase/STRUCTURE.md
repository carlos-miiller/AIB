## Directory Purposes

**`AIBWindows/`** — Primary production app. .NET 8 WPF for Win10/11.
- Purpose: Full ReAct AI assistant with tools, memory, voice, OCR, shadow observer.
- Contains: `App.xaml(.cs)`, `Services/`, `Views/`, `AIB.csproj`.
- Key files: `App.xaml.cs:26` (`OnStartup`), `Services/OpenAIService.cs:183` (`StreamResponseAsync`), `Services/ToolRegistry.cs:65` (`RegisterNativeTools`).

**`AIBWindows/Services/`** — Business / cognition / OS-adapter layer.
- Purpose: every non-UI concern. Tool implementations, LLM client, persistence, hardware adapters.
- Contains: ~25 `.cs` files, mostly static utility classes plus a handful of instance services (`OpenAIService`, `SettingsService`, `ShadowAssistantService`, `VoiceService`, `OcrService`).
- Key files (alphabetical):
  - `AIBWindows/Services/ChatHistoryService.cs` — past-session persistence (`chat_history.json`).
  - `AIBWindows/Services/CommandService.cs` — `cmd.exe /c` wrapper (20 s timeout, 50 KB cap).
  - `AIBWindows/Services/ContextService.cs` — static `ObservableCollection<ContextFile>` bound to sidebar.
  - `AIBWindows/Services/CredentialService.cs` — DPAPI-encrypted per-system credential vault.
  - `AIBWindows/Services/DefaultSkills.cs` — Seed Python/PowerShell skills (consultar_cep, system_info).
  - `AIBWindows/Services/DirectoryService.cs` — All filesystem paths in one place. Migrates from old `%AppData%\AIB`.
  - `AIBWindows/Services/DynamicSkillTool.cs` — `ITool` adapter around a `SkillMetadata`.
  - `AIBWindows/Services/FileService.cs` — `ReadFileForAIAsync` / `WriteFileAsync` / `ListDirectory`.
  - `AIBWindows/Services/ITool.cs` — Contract: `Name`, `Description`, `ChatToolDefinition`, `RequiredLevel`, `ExecuteAsync`.
  - `AIBWindows/Services/LevelService.cs` — XP→level (1–9) + level→max-tokens lookup.
  - `AIBWindows/Services/MemoryService.cs` — RAG (LiteDB + `SmartComponents.LocalEmbeddings` BGE micro v2 + cosine).
  - `AIBWindows/Services/NativeTools.cs` — 12 `ITool` implementations (44 KB single file).
  - `AIBWindows/Services/OcrService.cs` — `Windows.Media.Ocr` (pt-BR preferred). Active-screen + all-screens.
  - `AIBWindows/Services/OpenAIService.cs` — ReAct streaming loop, warmup, history management.
  - `AIBWindows/Services/ReminderService.cs` — Persistent reminders (`reminders.json`).
  - `AIBWindows/Services/ScreenshotService.cs` — Multi-monitor base64 JPEG.
  - `AIBWindows/Services/SettingsService.cs` — DPAPI-encrypted settings + Ollama `/api/tags`.
  - `AIBWindows/Services/ShadowAssistantService.cs` — Hover-dwell passive observer + LLM suggestions.
  - `AIBWindows/Services/ShadowHistoryService.cs` — In-memory Shadow log (cap 5).
  - `AIBWindows/Services/SkillService.cs` — Dynamic Python/PowerShell skills under `~/.AIB/skills`.
  - `AIBWindows/Services/SkillsShService.cs` — Online catalogue scraper (skills.sh API + `npx` fallback).
  - `AIBWindows/Services/ToolRegistry.cs` — `Dictionary<string, ITool>` + level-gated dispatch.
  - `AIBWindows/Services/VoiceService.cs` — NAudio capture + Whisper.net local transcription.
  - `AIBWindows/Services/WebSearchService.cs` — DuckDuckGo Instant Answer JSON.
  - `AIBWindows/Services/WindowTextExtractor.cs` — UI Automation tree walker (preferred over OCR).

**`AIBWindows/Views/`** — WPF windows and user controls (Acrylic / frameless / transparent).
- Purpose: presentation. Code-behind drives interaction; XAML drives layout.
- Contains: 5 `.xaml` + `.xaml.cs` pairs.
- Key files:

## Naming Conventions

**Files (C#):**
- One public type per `.cs`, PascalCase name matching the type (`OpenAIService.cs` → `OpenAIService`).
- Tool classes end in `Tool` (`ReadFileTool`, `RunCommandTool`).
- Service classes end in `Service` (`MemoryService`, `WebSearchService`).
- WPF window pairs: `<Name>Window.xaml` + `<Name>Window.xaml.cs`.

**Files (Python):**
- snake_case (`chat_window.py`, `openai_client.py`).
- Module-per-concern; class names PascalCase inside.

**Directories:**
- C# code lives under root-level capitalised folders (`Services/`, `Views/`).
- Python code lives inside lower-case package (`app/`).
- Documentation folders are Portuguese ASCII with accents (`documentação/`, `Regras de Identidade/`, `ideias_futuras/`).
- Markdown filenames in docs/ideas: numbered prefix `NN_Topic.md` (e.g. `01_Architecture_Overview.md`, `06_SidePanel_Contexto_Visivel.md`).

## Where to Add New Code

**New native tool (C# `ITool`):**
- Add a class to `AIBWindows/Services/NativeTools.cs` implementing `ITool`. Choose `RequiredLevel` based on capability (1=safe, 2+=I/O, 3+=network/screen, 5+=skill mutation, 7+=credentials, 9+=admin).
- Register it in `AIBWindows/Services/ToolRegistry.cs:65` inside `RegisterNativeTools()`.
- If it has a confirmation UI need, wire to `CommandConfirmationWindow` or build a parallel modal in `AIBWindows/Views/`.
- If documented behaviour needs the LLM to know about it, also update `documentação/04_Tools_and_Capabilities.md`.

**New service (C# business logic):**
- New file in `AIBWindows/Services/`. Match the existing static-vs-instance pattern (use `static` if state is filesystem-scoped, instance if it owns event handlers / mutable state per `ChatWindow`).
- If the service produces events, expose them as `event Action<...>?` (project convention, see `OpenAIService.OnTokenCountChanged`, `ShadowAssistantService.OnSuggestionReceived`).
- Inject by constructing in `AIBWindows/Views/ChatWindow.xaml.cs` constructor.

**New window / control (WPF):**
- Add `<Name>Window.xaml` + `<Name>Window.xaml.cs` to `AIBWindows/Views/` (or `<Name>.xaml` + `.xaml.cs` for `UserControl`).
- Match existing namespace `AIB.Views`.
- For Acrylic/blur and `Deactivated`-hide behaviour, copy the pattern from `SettingsWindow.OnSourceInitialized` and `ChatWindow.Window_Deactivated`.

**New dynamic skill (Python/PowerShell):**
- Two options:
  - Seed: add a `SkillMetadata` entry + `GetScriptContent` switch case to `AIBWindows/Services/DefaultSkills.cs`. It will be materialised on first run into `~/.AIB/.default_skills/<name>/`.
  - Materialise from LLM: have the agent call `materialize_skill` at runtime — it writes under `~/.AIB/skills/<name>/`.

**Settings field:**
- Add a property to `UserAppSettings` in `AIBWindows/Services/SettingsService.cs:12` with a default. The JSON serialiser handles round-trip automatically.
- Surface in UI: add the control to `AIBWindows/Views/SettingsWindow.xaml` and bind read/write in `SettingsWindow.xaml.cs`'s `LoadUiValues` / save handler.

**Persistent data file:**
- Add a `SomethingDir` / `SomethingPath` property to `AIBWindows/Services/DirectoryService.cs` so all path computation stays centralised.
- Call `Directory.CreateDirectory(...)` in `DirectoryService.EnsureDirectories()` (`DirectoryService.cs:28`).

**Linux side new code:**
- Files go into `AIBLinux/app/`.
- Register in `AIBLinux/main.py` if it needs to participate in process boot.
- Keep imports inside functions when they're slow (PyQt6 modules etc.) — the existing code does this in `_make_tray_icon` (`main.py:20`).

## Special Directories

**`~/.AIB/` (runtime, NOT in repo):**
- Purpose: per-user data root. Created by `DirectoryService.EnsureDirectories()`.
- Generated: yes (at first run).
- Committed: no.
- Subtree: `skills/`, `.default_skills/`, `memory/`, `logs/`, `credentials/`, plus `profile.dat`, `memory.db`, `memory.json`.

**`%LOCALAPPDATA%\AIB\Models\` (runtime):**
- Purpose: Whisper `ggml-base.bin` cache (downloaded on first voice activation).
- Generated: yes (lazy on `VoiceService.InitializeAsync`).
- Committed: no.

**`%AppData%\AIB\` (legacy + active runtime):**
- Purpose: `chat_history.json`, `reminders.json` still write here; old data root before migration.
- Migration: `DirectoryService.EnsureDirectories` copies content into `~/.AIB/` once.
- Generated: yes.
- Committed: no.

**`AIBWindows/bin/`, `AIBWindows/obj/`:**
- Purpose: MSBuild output.
- Generated: yes.
- Committed: no (gitignored).

**`.env` files (`./`, `AIBWindows/`, `AIBLinux/`):**
- Purpose: secrets (API keys, Ollama URLs).
- Generated: by user.
- Committed: no (gitignored).
- **Never read or quote contents.**
